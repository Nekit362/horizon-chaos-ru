# Апгрейдер: Хардкор для Horizon

Локальный перенос игровой механики **Upgrader 1.3.0** (EXEcheINZ) с Forge 26.1.2 на Rust/Horizon 26.3. Это самостоятельная реализация под API Horizon, а не Java-мод. Игровой код написан на Rust; Python нужен только разработчику для упаковки.

## Что реализовано

- **Апгрейдер выдаётся каждому игроку при первом входе в мир.** При заполненном инвентаре выдача ждёт свободного места. Повторный вход и смерть не выдают ещё один стартовый предмет.
- ПКМ с Апгрейдером или клавиша **U** открывает станцию. Клавишу можно переназначить в настройках мода.
- Ставка — весь стак из выбранной ячейки инвентаря. Предмет выигрыша выбирается в каталоге справа. Поиск работает по названию и идентификатору; Backspace удаляет символы, `<` и `>` меняют страницу.
- Кнопки **− / + / MAX** выбирают количество выигрыша от 1 до 64 с учётом собственного размера стака предмета. Для нестакаемых предметов максимум — 1. В оригинале 1.3.0 выбор количества уже был; здесь он сохранён.
- Шанс пересчитывается для всего выбранного количества. Ставка снимается сервером при нажатии «РИСКНУТЬ СТАВКОЙ», результат определяется серверным RNG и выдаётся через 80 тиков (4 секунды при 20 TPS).
- Во время ставки показывается **вращающееся круглое колесо** с неподвижной стрелкой, зелёным сектором выигрыша и красным сектором проигрыша. Площадь зелёного сектора соответствует реальному шансу. Когда сервер присылает результат, колесо плавно замедляется и останавливается на соответствующем секторе; затем результат остаётся виден ещё 1.8 секунды. Визуальное торможение продолжается после серверных 4 секунд и не меняет уже определённый выигрыш.
- Если выигрыш не помещается, он остаётся задолженностью и выдаётся после освобождения места. Закрытие интерфейса и выход из мира не отменяют ставку и не меняют результат.
- При полном инвентаре колесо всё равно показывает подтверждённый выигрыш: ожидание выдачи предметов не превращается в бесконечное вращение. Повторное открытие во время ставки восстанавливает её шанс, целевой предмет и количество; повторный пакет результата не запускает торможение заново.
- Стартовый предмет, ограничения попыток и незавершённая ставка хранятся в **сохраняемых данных самого игрока** вместе с его инвентарём. Смерть сохраняет эти данные, поэтому стартовую выдачу нельзя повторять самоубийством.
- Интерфейс и сообщения на русском. Названия ванильных предметов берутся из языка игры/сервера; для русских названий выберите русский язык Minecraft.
- Сохранён рецепт восстановления потерянного устройства: четыре золотых слитка в углах, четыре алмаза по сторонам, наковальня в центре.

## Хардкорный баланс

`шанс = min(65%, 0.55 × цена_всей_ставки / (цена_предмета_выигрыша × количество))`

В оригинале множитель — 0.9, верхний предел — 90%, нижний — 0.1%, попытки не ограничены. Здесь множитель **0.55**, предел **65%**, **3 попытки за скользящие 60 секунд** на игрока. Таймер ограничений использует реальное время; ожидание результата — серверные тики.

**Нижнего гарантированного шанса нет.** Иначе дешёвый мусор получал бы чрезмерный шанс на дорогой выигрыш. Одновременное умножение всех цен на одно число не меняет шанс, поэтому изменены именно соотношения цен:

| Предмет | Оригинал | Хардкор |
|---|---:|---:|
| Земля, булыжник | 1 | 0.25 |
| Древесина | 4 | 1 |
| Железный слиток | 40 | 80 |
| Золотой слиток | 60 | 160 |
| Изумруд | 140 | 320 |
| Алмаз | 400 | 2 000 |
| Незеритовый лом | 1 200 | 9 000 |
| Тотем бессмертия / трезубец | 1 500 | 16 000 |
| Элитры / зачарованное золотое яблоко | 2 500 | 30 000 |
| Звезда Незера | 4 000 | 50 000 |

Пример: один железный слиток на один алмаз — **2.2%**, на 16 алмазов — **0.1375%**. Все цены служат расчётными единицами; валюту мод не добавляет.

Производные предметы оцениваются по наиболее дешёвому полному рецепту из реально загруженных рецептов мира. Алмазный блок стоит 18 000, палка из дубовых досок — 0.125. Блоки, полученные обратимым крафтом, не дают искусственной прибыли. Предмет без известной исходной цены и полного рецепта не предлагается; неизвестный ингредиент никогда не считается бесплатным.

Креативные и технические предметы, яйца призыва, предметы с переменным содержимым и яйцо дракона недоступны. В качестве ставки запрещены повреждённые предметы и стаки с дополнительными компонентами: их содержимое/зачарования не оцениваются как обычный предмет.

После первого входа сервер пишет в папку мира `upgrader-effective-prices.json` — точную итоговую таблицу для загруженной версии и набора рецептов. Для переопределений создайте там `upgrader-prices.json`, например:

```json
{
  "minecraft:diamond": 2500,
  "minecraft:elytra": 50000,
  "minecraft:totem_of_undying": 0
}
```

Значение 0 запрещает предмет. Это **итоговые** цены; переопределения не распространяются на цены остальных рецептов. Перезайдите в мир или выполните `/reload`, затем откройте станцию заново.

## Установка

1. Нужен Horizon с поддержкой нативных модов, лаунчер 0.2.37 или новее. Этот порт закреплён за исходной ревизией `3a817511807aa1056cfcf2598a05180737751cc1` (Horizon 26.3).
2. Положите `dist/upgrader-content-0.1.0.hmod` в `horizon-mods` папки отдельного игрового экземпляра. Включите его в Options → Mods и перезапустите игру.
3. В той же папке игрового экземпляра создайте `horizon-native-mods` и положите туда `dist/upgrader-hardcore-0.1.0.hnmod`. В лаунчере выберите этот экземпляр, откройте Mods и выполните **Build** в строке Native build. Первая нативная сборка может занять 20–30 минут; дальнейшие изменения собираются быстрее. Для разработки из исходной папки доступна та же сборка командой:

   ```powershell
   horizon-launcher native-build "C:\Users\nikit\Documents\UpgraderHorizon\mixins\upgrader_hardcore" --trust-native-code
   ```

4. Запустите мир. Устройство выдаётся на первом живом серверном тике игрока.

Нативный мод нужен **на сервере и на клиентах**; content-мод также должен совпадать на обеих сторонах. Серверы обычного Java Minecraft этот порт не исполняют. Никакие пользовательские миры или настройки лаунчера во время разработки автоматически не изменялись.

## Отличия от оригинала и проверка

Колесо нарисовано заново средствами GUI Horizon: это круг с секторами и плавной анимацией, а не перенос Java-рендерера. Игровые страницы редактирования цен заменены серверным JSON. Оценка стоимости основана на базовых ценах и рецептах Horizon; это не побайтовая копия оригинального вычисления по Java loot tables. Предметы с дополнительными компонентами консервативно исключены из ставки.

Математика вероятностей, влияние количества, ограничения попыток, отсутствие субсидируемого минимального шанса, расчёт рецептов, попадание колеса в подтверждённый сервером сектор, плавность торможения и повторные пакеты результата проверяются `cargo test`: **6 тестов**. Состояние сборки интеграции и проверки упаковки записано отдельно в `VALIDATION.md`. Проверку настоящего игрового сеанса нельзя подменять этими тестами.

Чтобы пересобрать пакеты после изменения исходников: `py -3.9 tools/package.py`.

В архиве есть `preview/roulette-win.gif` — предпросмотр вращения и остановки, и `preview/roulette-outcomes.png` — сравнение конечных секторов для выигрыша и проигрыша. Углы для них вычислены запуском того же Rust-кода, что работает в моде; круг построен по той же геометрии. Это разработческий предпросмотр, **не скриншоты запущенной игры**.
